# Chess Cheating Signals

Бесплатное расширение для Chrome (Manifest V3): ставит бейджи на карточку соперника в партии на
chess.com по его статистике за последние часы. Только публичные данные из API завершённых партий —
без движка, подсказок и автоматизации. Без сборки — папка грузится как есть.

## Установка для разработки

1. `chrome://extensions/` → включить **Режим разработчика**
2. **Загрузить распакованное расширение** → выбрать папку проекта
3. Открыть партию на chess.com (`/play/online` или `/game/live/...`)

## Структура

```
manifest.json
fonts/                  Inter (вариативный, latin + cyrillic), OFL
svg/                    вся отображаемая графика
  badge-lucky|new|cold|high.svg
  indicator.svg         полоса побед/поражений (ширина зелёной части задаётся в рантайме)
src/content/
  settings.js           значения по умолчанию + chrome.storage.sync
  api.js                внутренний эндпоинт chess.com + откат на публичный API
  analyze.js            подсчёт W/L/D, точности и бейджей
  ui.js                 вставка бейджей в строку игрока
  index.js              наблюдение за страницей, оркестрация
  badges.css
src/popup/              настройки
src/i18n.js             загрузчик переводов (общий для страницы и попапа)
src/content/locale.js   определение языка интерфейса chess.com
i18n/<код>.json         55 языков chess.com, один файл на язык
_locales/<код>/         только имя и описание для Chrome Web Store, собирается из i18n/
tools/build-locales.mjs пересборка _locales
devtools/               данные, снятые с живой сессии (см. RESEARCH.md)
```

## Как это работает

Один POST-запрос на соперника отдаёт сразу всё: результаты партий, точность, дату регистрации,
устройство. Подробности и замеры — в [RESEARCH.md](RESEARCH.md), правила бейджей — в [SPEC.md](SPEC.md).

Запрос идёт из content script, то есть с самой страницы chess.com — куки сессии уходят
автоматически, CORS не мешает. Кэш на ник — 60 секунд.

Если внутренний эндпоинт отвечает не 200 (chess.com его уже менял), расширение автоматически
откатывается на публичный `api.chess.com/pub`: LUCKY, COLD, NEW и свой счёт продолжат работать,
HIGH пропадёт — в публичном API точности почти нет.

## Языки

Поддержаны все 55 языков интерфейса chess.com. Язык выбирается автоматически и в двух местах
по-разному:

| Где | Какой язык | Откуда берётся |
|---|---|---|
| подсказка и бейджи на странице | язык интерфейса chess.com | `src/content/locale.js` |
| попап настроек | язык браузера | `chrome.i18n.getUILanguage()` |

Язык сайта определяется по странице, по первому сработавшему признаку: `<html lang>` →
`<meta property="og:locale">` → `<meta http-equiv="content-language">` → префикс пути
(`/ru/play/online`) → `navigator.language`. В консоли видно, какой признак сработал:

```
[CCD] язык сайта: ru-RU (источник: html[lang]) → интерфейс: ru
```

Переводы лежат в `i18n/`, по файлу на язык, в плоском формате `{ "ключ": "строка с $1" }`.
`chrome.i18n` для них не годится: он жёстко привязан к языку браузера и переключить его на
язык сайта нельзя — поэтому загрузчик свой (`src/i18n.js`). Непереведённый ключ автоматически
показывается по-английски.

Как добавить или поправить язык:

1. отредактировать `i18n/<код>.json` (ключи те же, что в `i18n/en.json`);
2. новый язык — добавить код и самоназвание в `CCD.i18n.LANGUAGES` в `src/i18n.js`;
3. `node tools/build-locales.mjs` — пересобрать `_locales` (имя и описание для магазина).

Языков у Chrome меньше, чем у chess.com: для `af, az, be, bs, gl, hy, is, ka, nl-BE, sq, tk,
ur, zh-HK` карточка в магазине будет английской, а сам интерфейс расширения — переведённым.

Письмо справа налево (`ar`, `fa`, `he`, `ur`) включается атрибутом `dir` на подсказке и на
попапе; в CSS для этого используются логические свойства (`text-align: start`,
`margin-inline-start`).

## Разметка chess.com

Строка игрока — `.cc-user-block-component`. **Первая такая на странице — соперник, вторая — своя.**
Ник внутри неё — `.cc-user-username-component`. Наши элементы вставляются последним потомком
строки, после всех служебных узлов Vue (`<!---->`). Образец разметки: `devtools/dom/board.html`.

Vue перерисовывает строку и стирает вставленное, поэтому MutationObserver проверяет,
на месте ли наш узел и тот ли в нём ник, и перерисовывает при расхождении.

На странице профиля (`/member/*`) разметка другая: берём шапку
`.profile-header-container` с `data-username` и `data-user-uuid`. Якорь для вставки ищем
**без опоры на классы** — находим лист дерева, текст которого ровно равен нику, и цепляемся
к его родителю. Оттуда же бесплатно берётся uuid, так что скачивать HTML профиля не нужно.

Страницы, на которые внедряемся: `/play/*`, `/game/*`, `/live/game/*`, `/analysis/*`, `/member/*`.

## Проверено

- Логика на реальном ответе `devtools/02-response.json`: 7 партий за 12ч, 5/2/0, винрейт 71% →
  **LUCKY**; точность 77.6% по 3 разобранным партиям → HIGH не ставится; аккаунт 2020 года →
  NEW не ставится; устройство — телефон.
- Вставка в DOM на реальной разметке доски (jsdom): роли определяются верно
  (`HayatAhmad97` — соперник, `allaua` — своя), бейджи встают последним потомком строки,
  зелёная часть индикатора при 5:2 — 23.6 из 33 px, потеря узла детектится.
- Вставка в шапку профиля — на макете разметки, не на живой странице.
- Все 55 словарей сходятся с английским по ключам и по подстановкам `$1/$2/$3`;
  подсказка отрисована на 10 языках, попап снят на греческом, филиппинском, японском
  и арабском (справа налево) — в 292 px попапа всё умещается.

## Сайт

`docs/index.html` — одностраничный лендинг: что показывают бейджи, что расширение читает
и чего не делает. Самодостаточный HTML, без сборки и без ассетов из репозитория.

Хостится бесплатно на Vercel: проект `chess-signals` в команде `fbtools`, Root Directory —
`docs`, команды сборки нет, production branch — `main`. Адрес: **https://chess.fbextractor.com**
(CNAME `chess` → `f8159212a91446ee.vercel-dns-017.com` в Cloudflare, проксирование выключено).
Прежний `chess-signals.vercel.app` остаётся рабочим алиасом. Каждый пуш ветки `public` в `main`
деплоится автоматически.

До этого пробовались GitHub Pages (адрес с ником), is-a.dev (отказ: корневые поддомены только
про разработку ПО) и Cloudflare Workers (адрес с ником аккаунта). Возвращаться не к чему.

Ссылки на репозиторий в лендинге ведут на `maestroant/chess-cheating-signals`, кнопки
«Add to Chrome» — на `chromewebstore.google.com/detail/fnpboablfdjolmlogkmochacdlpeeacc`
(ID расширения в Chrome Web Store).

Публикуется не `master`, а ветка-снимок `public`: без `devtools/`, `SPEC.md`, `RESEARCH.md`
и `src/content/api.js`, с отдельным README и лицензией MIT. Пуш — `git push origin public:main`.

## Не доделано

- Роли определяются позицией строк. Если переворот доски (flip) меняет их порядок в DOM,
  бейджи уедут на свою карточку — нужно проверить и, если так, закрепить роли по нику
  из шапки сайта.
- `moveTimestamps` (время на каждый ход, есть у 100% партий) пока не используется.
