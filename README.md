# Chess Opponent Insights

Расширение для Chrome (Manifest V3): ставит бейджи на карточку соперника в партии на chess.com
по его статистике за последние часы. Без сборки — папка грузится как есть.

## Установка для разработки

1. `chrome://extensions/` → включить **Режим разработчика**
2. **Загрузить распакованное расширение** → выбрать папку проекта
3. Открыть партию на chess.com (`/play/online` или `/game/live/...`)

## Структура

```
manifest.json
fonts/                  Inter (вариативный, latin + cyrillic), OFL
svg/                    вся отображаемая графика
  badge-lucky|new|cold|high.svg
  indicator.svg         полоса побед/поражений (ширина зелёной части задаётся в рантайме)
src/content/
  settings.js           значения по умолчанию + chrome.storage.sync
  api.js                внутренний эндпоинт chess.com + откат на публичный API
  analyze.js            подсчёт W/L/D, точности и бейджей
  ui.js                 вставка бейджей в строку игрока
  index.js              наблюдение за страницей, оркестрация
  badges.css
src/popup/              настройки
_locales/en|ru/         тексты
devtools/               данные, снятые с живой сессии (см. RESEARCH.md)
```

## Как это работает

Один POST-запрос на соперника отдаёт сразу всё: результаты партий, точность, дату регистрации,
устройство. Подробности и замеры — в [RESEARCH.md](RESEARCH.md), правила бейджей — в [SPEC.md](SPEC.md).

Запрос идёт из content script, то есть с самой страницы chess.com — куки сессии уходят
автоматически, CORS не мешает. Кэш на ник — 60 секунд.

Если внутренний эндпоинт отвечает не 200 (chess.com его уже менял), расширение автоматически
откатывается на публичный `api.chess.com/pub`: LUCKY, COLD, NEW и свой счёт продолжат работать,
HIGH пропадёт — в публичном API точности почти нет.

## Разметка chess.com

Строка игрока — `.cc-user-block-component`. **Первая такая на странице — соперник, вторая — своя.**
Ник внутри неё — `.cc-user-username-component`. Наши элементы вставляются последним потомком
строки, после всех служебных узлов Vue (`<!---->`). Образец разметки: `devtools/dom/board.html`.

Vue перерисовывает строку и стирает вставленное, поэтому MutationObserver проверяет,
на месте ли наш узел и тот ли в нём ник, и перерисовывает при расхождении.

На странице профиля (`/member/*`) разметка другая: берём шапку
`.profile-header-container` с `data-username` и `data-user-uuid`. Якорь для вставки ищем
**без опоры на классы** — находим лист дерева, текст которого ровно равен нику, и цепляемся
к его родителю. Оттуда же бесплатно берётся uuid, так что скачивать HTML профиля не нужно.

Страницы, на которые внедряемся: `/play/*`, `/game/*`, `/live/game/*`, `/analysis/*`, `/member/*`.

## Проверено

- Логика на реальном ответе `devtools/02-response.json`: 7 партий за 12ч, 5/2/0, винрейт 71% →
  **LUCKY**; точность 77.6% по 3 разобранным партиям → HIGH не ставится; аккаунт 2020 года →
  NEW не ставится; устройство — телефон.
- Вставка в DOM на реальной разметке доски (jsdom): роли определяются верно
  (`HayatAhmad97` — соперник, `allaua` — своя), бейджи встают последним потомком строки,
  зелёная часть индикатора при 5:2 — 23.6 из 33 px, потеря узла детектится.
- Вставка в шапку профиля — на макете разметки, не на живой странице.

## Не доделано

- Роли определяются позицией строк. Если переворот доски (flip) меняет их порядок в DOM,
  бейджи уедут на свою карточку — нужно проверить и, если так, закрепить роли по нику
  из шапки сайта.
- Локали кроме `en` и `ru`.
- `moveTimestamps` (время на каждый ход, есть у 100% партий) пока не используется.
